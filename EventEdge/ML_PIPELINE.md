# ML-модели новостей EventEdge

В EventEdge решаются две разные ML-задачи:

- **значимость** — будет ли реакция акции заметной относительно рынка;
- **направление** — будет ли оставшееся движение акции выше или ниже рынка.

Обе модели принимают решение через пять минут после публикации. Это позволяет
учесть начальную реакцию цены и при этом сохранить короткую задержку для
пользователя.

## Датасет

Канонический датасет `canonical_v4_point_in_time_1238` содержит:

| Характеристика | Значение |
| --- | ---: |
| Строки | 1 238 |
| События | 1 226 |
| Независимые information groups | 1 108 |
| Период | 16.09.2024–04.09.2026 |
| Markettwits | 891 |
| BCS | 324 |
| Russianmacro | 12 |
| AK47 | 11 |

Для каждой новости сохранены текст, источник, тикер, время публикации и
минутные `open` акции и benchmark-индекса IMOEX2. SHA-256 датасета:
`ee47437edd61f2f444f32e1d85e7562fb0a07c47750651217ffc898c55ca632c`.

Точка принятия решения — `published_at + 5 минут`. Доходность считается от
первого доступного `open` после этой точки до четырёхчасовой границы:

```text
abnormal return = stock return - IMOEX2 return
```

Целевые переменные:

- `materiality_4h = 1`, если `abs(abnormal return) >= 0,5 п.п.`;
- `remaining_abnormal_4h = 1`, если abnormal return после первых пяти минут
  положительный, иначе `0`.

Связанные публикации остаются в одной information group. Оценка выполняется
хронологически с 72-часовым embargo, поэтому одна новость или один ценовой путь
не распределяются одновременно между train и evaluation.

## Признаки

Общая рыночная часть включает:

- доходность акции до события за 1 час, 1 день и 5 дней;
- часовую доходность IMOEX2;
- 20-дневную волатильность и 60-дневную beta;
- beta-adjusted движение перед событием;
- движение акции, IMOEX2 и abnormal return за первые пять минут;
- время публикации, торговую сессию, тикер и источник.

### Модель значимости

`update_5m_symmetric_materiality_logistic` дополнительно использует абсолютную
величину первой реакции:

- `abs(reaction_stock)`;
- `abs(reaction_abnormal)`;
- `abs(reaction_abnormal) / volatility`.

Модель не использует текст новости и LLM-признаки. Её задача — оценить
вероятность заметной реакции, а не определить направление цены.

### Модель направления

`update_5m_corrected_reaction_interactions` дополняет рыночные признаки
структурой события:

- категория и стадия события;
- роль эмитента;
- disposition события;
- взаимодействие категории и стадии со знаком первой реакции.

Эти признаки были приведены к единому контракту после исправления ошибок в
исторической разметке.

## Обучение и оценка

Обе модели — L2-регуляризованные логистические регрессии (`C=0.1`). Числовые
признаки масштабируются только по train, пропуски заполняются нулём после
масштабирования, категориальные признаки кодируются one-hot. Вероятности
калибруются сдвигом logit, рассчитанным только на validation.

Benchmark состоит из семи последовательных monthly walk-forward окон. В общую
оценку вошли 480 строк. Пороги coverage выбираются на validation, а не на
evaluation.

## Результаты

| Модель | Основные метрики | Итог |
| --- | --- | --- |
| Значимость | raw ROC-AUC `0,7050`, PR-AUC `0,6817`; calibrated ROC-AUC `0,6905`, Brier `0,2228` | Используется для оценки и ранжирования значимых новостей |
| Направление | ROC-AUC `0,4982`, hit rate `49,58%` | Не даёт устойчивого преимущества |
| Market-only для направления | ROC-AUC `0,5073`, hit rate `50,63%` | Лучше directional ML по основным метрикам |
| Always-down | hit rate `53,13%` | Показывает сильный исторический class prior |

Для модели значимости precision составил `68,81%` при coverage `22,71%` на
validation-пороге. Добавление абсолютных признаков первой реакции повысило
calibrated AUC относительно signed-reaction/context baseline на `0,0434`;
day-cluster bootstrap 95% CI: `[0,0155; 0,0711]`.

На пересечении из 157 исторических строк с формулой config 6 directional ML
получила hit rate `51,59%`, формула — `50,96%`. Интервал парной разницы
`[-12,10; 12,42] п.п.` включает ноль, поэтому это отличие не считается
подтверждённым.

## Inference модели значимости

В рабочем pipeline модель значимости применяется так:

1. После определения новости и тикера система ждёт пять минут от публикации.
2. Загружает causal history акции и IMOEX2 и строит тот же набор признаков,
   который использовался при обучении.
3. Переносимая JSON-модель вычисляет raw и calibrated probability без `pickle`
   и зависимости от scikit-learn в runtime.
4. Результат вместе с `data_cutoff_at`, версиями модели и признаков сохраняется
   в `materiality_predictions`.
5. `GET /v1/news` возвращает поле `market_materiality`; интерфейс показывает
   вероятность заметной реакции и, в зависимости от rollout-режима, может
   использовать её для ранжирования новостей.

### Rollout-режимы

Режим задаётся переменной `NEWS_MATERIALITY_MODE`:

| Режим | Работа модели | API и порядок новостей |
| --- | --- | --- |
| `disabled` | Значение по умолчанию. Модель не загружается, признаки не запрашиваются, предсказания не вычисляются. | `market_materiality` отсутствует, существующий порядок новостей не меняется. |
| `shadow` | Каждые пять минут система вычисляет и сохраняет предсказания для поддерживаемых новостей. | API и интерфейс показывают вероятность; пользователь может выбрать сортировку по ML-значимости, но исходный порядок по умолчанию сохраняется. |
| `rank` | Выполняется всё из `shadow`; источник может быть любым, а для ранжирования требуются известный модели тикер и доступная пятиминутная реакция. | Backend переставляет только оценённые строки внутри уже занятых ими позиций одного UTC-дня. Свежие, ожидающие расчёта и неподдерживаемые новости сохраняют свои позиции. |

Во всех режимах модель оценивает вероятность движения не менее `0,5 п.п.`
относительно IMOEX2 за четыре часа. Она не предсказывает направление, не
заменяет формулу сигнала `signal-engine-0.6.1` и не меняет её config 7.
Пятиминутная точка — это cutoff признаков; поскольку фоновая задача запускается
раз в пять минут, результат обычно появляется через 5–10 минут после
публикации.

Версия рабочей модели:
`update-5m-symmetric-materiality-logistic-1.0`. Артефакт находится в
`src/eventedge/models/news-materiality-v1.json` и проверяется по встроенному
SHA-256 перед загрузкой.

Directional-модель сохранена как воспроизводимый исследовательский артефакт,
но не используется для определения направления сигнала из-за результатов
benchmark.

Дополнительная серия development-проверок RuBERT, альтернативных горизонтов,
selective prediction, structured features и малых нелинейных моделей сохранена
в [архиве этапов 1–5](NEWS_DIRECTION_EXPERIMENTS.md). Она использует предыдущую
версию датасета и другое определение directional horizon, поэтому не подменяет
метрики этого canonical benchmark без отдельного rerun.

## Код и артефакты

- Сбор кандидатов: `download_telegram_archive.py`,
  `build_telegram_archive_candidates.py`, `build_ydb_signal_candidates.py`.
- Рыночные данные и labels: `download_moex_market_opens.py`,
  `download_moex_index_opens.py`, `build_signal_dataset.py`.
- Признаки и benchmark: `prepare_news_model_data.py`,
  `evaluate_news_models.py`.
- Обучение и offline inference: `fit_news_materiality_model.py`,
  `fit_news_direction_model.py`, `predict_news_materiality.py`,
  `predict_news_direction.py`.
- Рабочий inference значимости: `src/eventedge/materiality.py` и
  `src/eventedge/materiality_pipeline.py`.

Точный состав датасета и параметры оценки закреплены в
[`DATASET_LINEAGE_CONTRACT.json`](DATASET_LINEAGE_CONTRACT.json) и
[`NEWS_MODEL_BENCHMARK_CONTRACT.json`](NEWS_MODEL_BENCHMARK_CONTRACT.json), а
полные метрики и SHA-256 — в
[`ML_ARTIFACT_MANIFEST.json`](ML_ARTIFACT_MANIFEST.json).

## Ограничения результатов

- Датасет является historical research proxy, а не независимым untouched test.
- Исторические Telegram-посты отражают доступную архивную версию; исходное
  время первого получения части записей восстановлено приближённо.
- Семантические признаки направления происходят из нескольких поколений
  extractor и не являются human gold-разметкой.
- В данных встречаются связанные публикации одного события; это учтено через
  information groups, но уменьшает эффективный размер выборки.
- Доходности не корректируются на все корпоративные действия, комиссии,
  ликвидность и проскальзывание.
