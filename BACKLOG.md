# EventEdge backlog

## P0 — Active: сделать текущий продукт понятным

Цель инкремента: пользователь за один экран понимает, что произошло, почему появился сигнал, на каком горизонте он действует и насколько сильным может быть движение. Все оценки остаются проверяемыми и не маскируются под точный прогноз.

- [x] Favicon: компактный знак на основе выбранного логотипа №5, читаемый в 16–32 px.
- [x] Локальные логотипы компаний: без внешней загрузки во время работы интерфейса, с fallback для неизвестных тикеров.
- [x] Источники в методике: роль, качество, свежесть, статус подключения и ссылка на каждый источник.
- [x] Нормализация событий: несколько публикаций об одном событии объединяются в одну карточку, подтверждающие источники сохраняются.
- [x] Рыночные данные MOEX: цена, изменение, объём, ликвидность, волатильность и дневные свечи через API snapshot компании.
- [x] Signal Card 2.0: направление, горизонт, цена расчёта, уверенность модели, сценарный диапазон движения и цветные события разного веса.

### Definition of Done

- Карточка отвечает на вопросы: что делать, почему, на каком горизонте и при каких условиях сигнал перестаёт быть актуальным.
- «Уверенность модели» не называется вероятностью, а скор не показывается как проценты роста.
- Диапазон движения явно назван сценарным, рассчитывается из рыночной волатильности и силы сигнала и не выдаётся за таргет цены.
- При отсутствии данных интерфейс честно показывает, что метрика недоступна; демонстрационные числа не подмешиваются в production.
- Клик по событию открывает исходную новость, а несколько подтверждений одного события видны как группа источников.
- API, UI, тесты и production-deploy проверены end-to-end.

## P0.1 — Active: скорость и плотность данных

Цель инкремента: первый полезный экран появляется до загрузки рыночных данных, котировки обновляются без перезагрузки, а новостной фон и события читаются на одной временной шкале с ценой.

- [x] Прогрессивная загрузка: новости и сигналы не ждут MOEX snapshot.
- [x] Batch API котировок: до 20 тикеров одним запросом с частичными ошибками.
- [x] Минутное обновление: polling раз в 60 секунд, пауза в скрытой вкладке и честный статус свежести.
- [x] График 2.0: цена, объём и кликабельные события на одной временной шкале; отдельная карта событий удалена.
- [x] Расширенная лента: 30-дневный discovery, фоновые новости сохраняются без LLM и без автоматического сигнала.
- [x] Диагностика ленты: количество публикаций, сигналов и последнее событие по каждому источнику.
- [x] Производительность доставки: gzip для HTML/API/JS и долгий cache-control для версионированных ассетов.

### Definition of Done

- Пользователь видит сигналы и новости сразу после ответа основного API, даже если MOEX отвечает медленно.
- Одно обновление интерфейса вызывает один batch-запрос котировок, а не запрос на каждую компанию.
- Кружок события расположен на дате публикации, цвет показывает направление, размер — вес, клик открывает новость.
- Фоновая публикация видна в ленте, но не вызывает LLM и не создаёт сигнал без прохождения строгого фильтра.
- Тестовая production-новость скрыта из публичных API.
- API, UI, OpenAPI, gateway и production deployment проверены end-to-end.

## P0.2 — Active: быстрые новости

Цель инкремента: новая публикация из приоритетного прямого RSS появляется в EventEdge за 1–2 минуты, при этом широкий discovery и медленные источники не задерживают основной контур и не раздувают расходы.

- [x] Fast lane: Интерфакс, ТАСС, РБК и Московская биржа проверяются каждую минуту.
- [x] Независимые контуры: Google News обновляется каждые 5 минут, Банк России — каждые 15 минут.
- [x] Изоляция ошибок: недоступность одного RSS не останавливает остальные источники.
- [x] Экономный повторный опрос: после пяти известных релевантных публикаций проход останавливается; повтор не вызывает LLM.
- [x] Время получения: `received_at` фиксирует фактический вход материала в EventEdge, а не копирует время публикации.
- [x] Быстрый UI: лента обновляется каждые 30 секунд и сразу обновляется после возврата во вкладку.
- [x] Публичный API: meta описывает частоту сбора, частоту обновления клиента, целевую задержку и состав контуров.

### Definition of Done

- Основные источники запускаются минутным Yandex Cloud Timer `* * ? * * *`.
- Целевая задержка от появления материала в приоритетном RSS до EventEdge — не более 120 секунд при доступном источнике и штатном ответе LLM.
- Новая публикация не ждёт Google News, Банка России или другого упавшего фида.
- Повторно известные записи проходят идемпотентно и не создают дубли или повторные LLM-вызовы.
- API, UI, OpenAPI, timers и production deployment проверены end-to-end.

## P1 — On hold: доказать качество сигнала

- [x] Evals MVP: реакция после сигнала на горизонтах 1 час / 1 день / 3 дня, hit rate, покрытие и средняя направленная реакция.
- [x] Демо-счёт MVP: сделки по правилам, доля счёта, комиссия и slippage; реальные заявки не отправляются.
- [x] **P1.2:** не-LLM факторы — реакция цены, объём, волатильность, ликвидность и доступные данные отчётности.
- [x] Live-оценка всего наблюдаемого рынка: hybrid при наличии свежей сильной новости, quant-only при её отсутствии.
- [x] Слабый рыночный уклон визуально отделён от сильного сигнала: цвет виден от ±5 пунктов, торговое действие появляется только после порога ±18.
- [ ] Point-in-time backtest и калибровка направления, диапазона и confidence на достаточной выборке.
- [ ] Полноценный фундаментальный датасет из первичной отчётности, а не только распознанные раскрытия.
- [ ] Сравнение демо-счёта с индексом полной доходности и формальные правила одновременных позиций.
- Новые Telegram-источники, раскрытие эмитентов и расширение рыночного новостного фона.
