# EventEdge backlog

## P0 — Active: сделать текущий продукт понятным

Цель инкремента: пользователь за один экран понимает, что произошло, почему появился сигнал, на каком горизонте он действует и насколько сильным может быть движение. Все оценки остаются проверяемыми и не маскируются под точный прогноз.

- [x] Favicon: компактный знак на основе выбранного логотипа №5, читаемый в 16–32 px.
- [x] Локальные логотипы компаний: без внешней загрузки во время работы интерфейса, с fallback для неизвестных тикеров.
- [x] Источники в методике: роль, качество, свежесть, статус подключения и ссылка на каждый источник.
- [x] Нормализация событий: несколько публикаций об одном событии объединяются в одну карточку, подтверждающие источники сохраняются.
- [x] Рыночные данные MOEX: цена, изменение, объём, ликвидность, волатильность и дневные свечи через API snapshot компании.
- [x] Signal Card 2.0: направление, горизонт, цена расчёта, уверенность модели, сценарный диапазон движения и цветные события разного веса.

### Definition of Done

- Карточка отвечает на вопросы: что делать, почему, на каком горизонте и при каких условиях сигнал перестаёт быть актуальным.
- «Уверенность модели» не называется вероятностью, а скор не показывается как проценты роста.
- Диапазон движения явно назван сценарным, рассчитывается из рыночной волатильности и силы сигнала и не выдаётся за таргет цены.
- При отсутствии данных интерфейс честно показывает, что метрика недоступна; демонстрационные числа не подмешиваются в production.
- Клик по событию открывает исходную новость, а несколько подтверждений одного события видны как группа источников.
- API, UI, тесты и production-deploy проверены end-to-end.

## P1 — On hold: доказать качество сигнала

- Point-in-time backtest, outcomes и калибровка направления, диапазона и confidence.
- Фундаментальные и отчётные признаки в отдельном детерминированном контуре.
- Демо-счёт, сделки по правилам, комиссии, slippage и сравнение с индексом полной доходности.
- Новые Telegram-источники, раскрытие эмитентов и расширение рыночного новостного фона.

## P2 — On hold: операционный продукт

- Полноценные API событий, feedback и оставшиеся admin endpoints.
- Админка источников, правил скоринга, качества данных и ручной модерации.
- Мониторинг, алерты, SLO, аудит моделей и контроль бюджета.
- Object Storage, Message Queue и Lockbox при подтверждённой потребности по нагрузке или безопасности.

## P3 — On hold: формализация и масштабирование

- Детальный PRD после проверки P0/P1 на реальных данных.
- Формальные GitHub Issues/roadmap только по решению владельца продукта.
- Расширение на новые классы активов и внешних пользователей.

Элементы со статусом **On hold** не попадают в текущую реализацию без отдельного решения владельца продукта.
